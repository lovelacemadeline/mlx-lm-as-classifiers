# Battery format

A battery is a JSONL file. Each line is a [wire-schema](wire-schema.md)
request (`prefix`, `state`, `questions`, optional `model` / `options`) plus
three reserved keys that are stripped before the request is validated:

```json
{"id": "robot-05~p1",
 "prefix": "You are a robot controller. The robot is in a room. Decide the next action.",
 "state": "Wall 10 cm ahead. Doorway to the left. Battery 80%.",
 "questions": {"action": {"type": "choice", "instructions": "What should the robot do next?",
                          "criteria": {"forward": "drive straight ahead", "left": "turn left",
                                       "right": "turn right", "stop": "stop and stay still"}}},
 "gold": {"action": "left"},
 "tags": {"source": "agent-robot", "difficulty": "near-miss", "group": "robot-05", "variant": "p1"}}
```

- **`id`**: unique within the file. A perturbation of case `X` is `X~pN`.
- **`gold`**: one entry per question, nothing else. `choice`: an option name
  from `criteria`. `noul`: `true` (yes) or `false` (no). `score`: the level
  index, lowest level is 0. These are the label conventions the `calibrate`
  command reads, so battery results can be refitted directly.
- **`tags`**: string values. `source` (which slice) and `difficulty` (`easy`,
  `hard`, `near-miss`) are required; accuracy is reported per tag value.
  A perturbation group adds `group` (the base case id, on every member) and
  `variant` (`base` or `pN`); every member of a group has the same gold, and the
  battery runner reports how often a variant's answer differs from the base's.

The loader is `mlx_classifiers.battery.load_battery`; it rejects a bad line
with `file:line`. The seed set is `battery/seed.jsonl`, generated by
`battery/build_seed.py`; story 5.1 describes its slices.
