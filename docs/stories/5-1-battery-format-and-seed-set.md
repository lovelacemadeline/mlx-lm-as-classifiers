# Story 5.1 — Battery format and a seed set of labelled decisions

A JSONL battery: each line is a wire-schema request plus gold answers. Seed it
with a few hundred cases: a slice of a public text-classification set for
`choice`, yes/no cases for `noul`, an ordinal sentiment or severity set for
`score`, and a hand-written set of agent-routing cases in the style the
library will actually see. The format is documented in
[battery-format](../reference/battery-format.md).

## Acceptance Criteria
- **Given** the battery file **when** every line is parsed **then** each
  validates against the request schema and names a gold answer among its
  declared options.
- **Given** a line with a gold outside its options, a missing question gold, a
  missing `source`/`difficulty` tag, an unknown top-level key, a duplicate id,
  or a perturbation group whose members disagree on gold **then**
  `load_battery` raises `BatteryError` naming `file:line`.
- **Given** the seed set **then** it has at least 300 cases covering all three
  question types, at least 60 hand-written routing cases, and at least 25
  perturbation groups (15+ near-miss) of 2 to 3 prefix variants each, including
  the probe's flipping case verbatim.

## Seed material from the first real probe (2026-10-16, E2B qat-4bit, first-token mode)

A four-way robot `choice` (forward / left / right / stop) with prefix "You are a
robot controller. Decide the next action." The model is responsive to the
state but marginal on the hard case, and the marginal case flips with
incidental prompt text, which is exactly what the battery must catch:

| state | choice | top p |
|---|---|---|
| wall 10 cm ahead, doorway to the left | left | 0.60 |
| same, plus "The robot is in a room." in the prefix and "Battery 80%." in the state | forward | 0.83 |
| path ahead clear 5 m, wall to the left | forward | 0.95 |
| robot on fire, battery 2% | stop | 0.97 |
| obstacle ahead, only open direction is right | right | 0.98 |

Position bias was ruled out for the wrong case: permutations=4 and moving
`forward` to the last slot both still chose forward, and sequence mode agreed.
So the battery needs a hand-written block of near-miss agent cases like the
second row, not only obvious ones, and should report the flip rate under small
prefix perturbations.

## Implementation notes
- `battery/seed.jsonl` (343 cases) is generated by `battery/build_seed.py`;
  both are committed, so a diff of the JSONL is a diff of the battery.
  Slices (`tags.source`): `hand-routing` 64 (40 support-triage tickets over
  billing / technical / sales / account, 24 home-assistant intents over five
  skills), `arc-challenge` 50, `hand-noul` 60 (balanced yes/no), `hand-score`
  60 (30 severity on a 4-level scale, 30 sentiment on a 5-level scale),
  `agent-robot` 59 and `agent-router` 50.
- No public text-classification set is in the local HF cache (it holds
  ai2_arc, gsm8k, tulu-3-sft-mixture and wikitext), so the `choice`
  classification slice is the 64 hand-written routing cases. A 50-question
  slice of ARC-Challenge validation (CC BY-SA 4.0, four-option questions only)
  is added as a public multiple-choice slice; it is QA, not classification, and
  is there as a hard slice where the model is often wrong, which is what makes
  ECE informative. It was extracted once from the cached parquet into
  `battery/sources/arc-challenge-validation-50.jsonl`; option names are the
  answer texts (no descriptions), so permutations reorder real content.
- Agent block: 16 robot cases (forward / left / right / stop) and 14
  coding-agent step-routing cases (search_docs / run_tests / edit_file /
  ask_user / finish), 11 easy and 19 near-miss. Each is a perturbation group:
  the base case plus 2 to 3 prefix variants that add incidental text ("The
  robot is in a room.", "Today is Tuesday.", "The user is a developer.") or
  reword the role, with the same gold. `robot-01` and `robot-05` are the
  probe's first two rows; `robot-05~p1` is the probe's flipping prompt
  verbatim (both the prefix sentence and "Battery 80%.").
- `gold` per question: option name (`choice`), bool (`noul`, true = yes),
  level index (`score`), the same conventions `fitting.label_index` reads, so
  battery results feed `calibrate` directly. `BatteryCase.gold` holds the
  resolved option index.
